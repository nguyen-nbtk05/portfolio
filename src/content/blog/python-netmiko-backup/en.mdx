# Automating configuration backups with Python and Netmiko

> **Demo content:** This article is sample data for testing the portfolio blog. Replace it with production-reviewed guidance before using it in a real network.

A configuration backup is most useful when it is **repeatable, searchable, and easy to restore**. This small lab workflow connects to a known inventory, collects each running configuration, and stores a timestamped copy without changing the device.

## What the lab covers

- Reading device details from a simple inventory.
- Connecting over SSH with `Netmiko`.
- Saving one UTF-8 text file per device.
- Recording failures without stopping the entire job.
- Comparing later backups to spot configuration drift.

The example deliberately keeps credentials in environment variables. For a real deployment, use a secrets manager and a dedicated read-only automation account.

## Sample inventory

| Name | Platform | Management IP | Command |
| --- | --- | --- | --- |
| branch-rtr-01 | Cisco IOS | `10.20.0.11` | `show running-config` |
| branch-sw-01 | Cisco IOS | `10.20.0.21` | `show running-config` |
| edge-fw-01 | Linux lab | `10.20.0.31` | `show configuration` |

Keep the inventory in version control, but never commit passwords or private keys. The [Netmiko documentation](https://ktbyers.github.io/netmiko/) lists supported `device_type` values and platform-specific behavior.

## Minimal backup script

```python
from datetime import datetime, timezone
from pathlib import Path
import os

from netmiko import ConnectHandler

devices = [
    {
        "name": "branch-rtr-01",
        "device_type": "cisco_ios",
        "host": "10.20.0.11",
    },
    {
        "name": "branch-sw-01",
        "device_type": "cisco_ios",
        "host": "10.20.0.21",
    },
]

output_dir = Path("backups")
output_dir.mkdir(exist_ok=True)
stamp = datetime.now(timezone.utc).strftime("%Y%m%dT%H%M%SZ")

for device in devices:
    connection = ConnectHandler(
        **device,
        username=os.environ["NET_USERNAME"],
        password=os.environ["NET_PASSWORD"],
    )
    try:
        config = connection.send_command("show running-config")
        destination = output_dir / f"{device['name']}-{stamp}.cfg"
        destination.write_text(config + "\n", encoding="utf-8")
        print(f"saved {destination}")
    finally:
        connection.disconnect()
```

Run the script only from a host that already has approved management access:

```bash
python -m venv .venv
python -m pip install netmiko
python backup_configs.py
```

## Make failure visible

A scheduled job should return a non-zero exit code when any device fails. It should also log the device name, failure category, and timestamp while avoiding secrets. Useful categories include:

1. DNS or TCP connection failure.
2. Authentication failure.
3. Command timeout.
4. Empty or suspiciously short output.
5. File-system or repository write failure.

For drift detection, normalize volatile lines such as timestamps before computing a hash or text diff. A changed checksum is a signal to review—not automatic proof of an incident.

```text
branch-rtr-01  OK      14,821 bytes  changed
branch-sw-01   OK      11,403 bytes  unchanged
edge-fw-01     FAILED  authentication
```

## Validation checklist

- [ ] Backups run from an approved management network.
- [ ] The automation account has the minimum required privileges.
- [ ] Secrets never appear in logs or the Git history.
- [ ] At least one backup has been restored in a lab.
- [ ] Retention and encryption match the organization's policy.
- [ ] Alerts identify partial success as well as total failure.

---

The important test is recovery: select a recent file, compare it with the intended configuration, and rehearse the restore procedure on a non-production device. A backup that has never been restored is only an assumption.
